# Union 组织目录同步与组织头像

2026-10-21。此功能接续 [OAuth 与成员访问](union-oauth-member-access.md)，将原先手工接入改为后台每分钟自动发现、创建组织与来源映射；不识别高校，不创建管理员。

## 目录同步原理

独立 Worker 从固定的 [联盟站点 API](https://skin.mualliance.ltd/api/union) 读取 `servers[].code`、`bs_root` 和 `version`。该接口没有组织名称、负责人或头像字段，因此新组织的初始别名使用 CODE；本地组织别名始终由用户维护。组织简介默认从各站公开 Yggdrasil 元数据同步，人工修改后保留人工内容。

- 每 60 秒同步目录，Worker 每 10 秒检查到期任务。启动即检查；数据库租约保证多 Worker 只执行一次，网络请求不占用业务事务。
- CODE 接受实际名单中的 1–6 位大写字母／数字，首位必须为字母，例如 `NPU`、`MUA`、`TEST2`。账号仍按完整 `CODE:ID` 区分。
- 新 CODE 没有映射时，若有唯一的同名本地组织就关联它；完全不存在则创建组织。存在多个同名组织或同名组织已归档时，跳过并报告冲突，不推断高校或迁移身份。
- 同 CODE、同地址去重；同 CODE、不同地址通常跳过，显示 `DUPLICATE_CODE`。已确认的 YITUEM 合并组织例外见下节，其他 CODE 不自动套用该规则。
- 既有 CODE 对应的 Organization UUID 永不自动改变。自动维护的站点地址可更新；管理员手动修改过的映射优先，不被上游地址覆盖。停用状态、组织归档、成员及角色均保留。
- 名单移除只改变上游出现标记，不删除组织、停用账号或撤销既有映射；再次出现仍复用原 UUID。网络失败、无效 JSON 或空名单保留原有事实，下个周期重试。
- 新建组织没有管理员或成员。用户经 Union OAuth 登录后才创建普通成员，仍没有管理、审核或发布角色。

### 皮肤站名称与组织简介（2026-10-22）

[授权页](https://skin.mualliance.ltd/api/union/oauth2/authorize) 的内联脚本先使用 CODE 创建按钮，再请求 `bs_root + /api/yggdrasil`，以 JSON 的 `meta.serverName` 替换文字；之后单独查询 `/api/union/member` 判断 OAuth 支持情况。截图中的先 CODE、后别名就是这些异步请求完成的结果。此次只读核对：MUA 返回“MUA 用户中心”、NPU 返回“NPUskin”、FDC 返回“FDCraft 用户中心”，YITUEM 两个已确认域名均返回“YIT & UEM 联合皮肤站”。站点名称不作为身份或管理权限来源。

- 目录每分钟同步时，Worker 在事务外获取 `meta.serverName`，只写入组织 **简介 description**，不覆盖 `displayName`、CODE、UUID 或成员。使用与头像相同的受保护网络读取器：无凭据 HTTPS、公开地址检查、DNS 固定及逐跳重定向验证，沿用 Worker 代理设置。不会调用登录或用户信息接口。
- 元数据只接受 JSON，响应上限 64 KiB，名称去首尾空白后为 1–200 字符，拒绝控制和不可见格式字符。以普通文本保存并由 React 转义展示。每地址最多 8 秒，每站包括别名最多 16 秒，并发 6，总元数据阶段最多 60 秒；目录租约调整为 90 秒。优先获取尚无简介的站点，任务完成后立即处理下一个；YITUEM 主站失败或单地址超时后尝试已确认的备用域名。
- `Organization.descriptionMode` 默认为 `AUTO`。首次导入和之后名称变化都更新简介；同名不重复改写。一个组织有多个 CODE 时，固定选择当前有效来源中字母顺序最前的 CODE，该来源失败时保留旧值。
- 有 `ORG_EDIT` 的用户仍可在组织编辑中修改简介。数据库触发器在真实修改或清空时将模式锁定为 `MANUAL`，之后目录同步和网页写入均不能恢复自动模式。只编辑组织别名或原样保存简介不停止自动同步；网页不重复提交未改动的简介，避免旧表单覆盖后台刚同步的内容。
- 迁移 `202610220003_union_site_descriptions` 将既有非空简介、以及审计中曾人工提交简介（包括清空）的组织标记为 `MANUAL`，保守保护已有资料。新建组织直接填写非空简介也归为人工内容。当前不提供恢复自动同步操作。
- 请求失败、无效或空名称不清空既有简介，也不妨碍创建组织；同步问题列记录 `SITE_NAME_UNAVAILABLE`。停用来源、归档组织和人工简介不抓取名称，也不接受自动写入。提交时再次检查来源地址、启用状态和人工模式，保留抓取期间发生的人工修改。
- Worker 仍只能通过持有租约的受限 `union_apply_sites` 函数写入，未增加通用组织写权限、业务表或 HTTP 字段。OpenAPI 保持 4.0.0（完整 88／公开 11），补充既有组织 PATCH 的行为说明。

## 组织皮肤站地址

### YITUEM 合并组织

用户已确认 `https://skin.yitmc.cn` 与 `https://skin.uemcraft.cn` 属于合并后的同一组织。目录解析只对这两个确切地址的组合放行：创建一个别名为 `YITUEM` 的组织和一个 CODE 映射，前者作为主地址、后者保存在 `bsRootAliases`。无论上游顺序如何，保存顺序固定，重复同步不增加组织或映射修订。

迁移 `202610210004_yituem_skin_site_aliases` 新增地址别名数组，数据库约束及 Worker 受限函数只允许上述已确认组合。未知第三地址仍报告冲突，不自动扩展；已存在的组织 UUID、人工映射和停用／归档状态仍保留。主地址被人工改写时清除旧别名，避免挂错地址。

账号仍使用完整 `YITUEM:ID` 作为身份，两个域名不会生成两个来源 CODE 或重复成员。此规则不合并本地账号、不授予管理权限；如果上游两个旧账号实际返回相同 `sub`，本地遵循上游给出的同一身份，不能仅凭域名区分它们。网站头像先尝试主地址，失败后在同一总超时内尝试别名地址，仍遵守人工头像优先。

组织资料和组织列表自动展示已启用 Union 来源映射的 `bs_root`，无需重新导入或手工补填。地址为只读字段，与目录每分钟同步的结果保持一致；手工维护过的映射仍按上述规则优先保留，不重复存储一份可能失配的组织地址。

列表右侧提供“前往皮肤站”，在新标签页打开对应 HTTPS 地址。一个组织存在多个地址时分别显示链接按钮，以域名区分；没有已启用来源时显示“暂无皮肤站地址”，跳转按钮禁用。地址也参与列表搜索。

管理状态 API 的组织对象新增可选 `skinSites: [{ code, url }]`。迁移 `202610210003_organization_skin_site_read` 允许已登录的本组织有效管理会话读取对应映射，仍由应用层过滤启用状态；其他组织的映射不可读，全局映射接口及修改操作仍仅限超管。没有新增业务表。

## 网站图标自动导入

“网站头像”按皮肤站网站图标理解。目录 API 不提供图标地址，因此使用 `bs_root` 进行发现，而不猜测不存在的头像 API：

1. 请求站点首页，解析 `link rel="icon"`、`shortcut icon`、`apple-touch-icon` 声明，相对地址按站点根路径解析。
2. 未找到可用声明时尝试站点路径和域名根路径的 `favicon.ico`。最多尝试 6 个去重候选。
3. 支持静态 PNG／JPEG／WebP，以及 ICO 内的 PNG 或受限 24／32 位 BMP。拒绝 SVG、动画和不可解码内容，继续尝试下一个候选；失败不阻止组织创建。
4. 默认中央正方形裁剪，输出精确 **512×512 WebP**。保留归一化原图、选区和 SHA-256 元数据，使用与人工上传相同的私有对象存储；浏览器不直接加载第三方图标。
5. 首次导入独立排队，每批最多 6 个组织、并发 3 个。成功后每天检查；失败一小时后重试。多个 CODE 映射同一组织时按 CODE 排序选择首个站点。内容摘要相同则不重复保存或增加头像修订。

所有请求限定无凭据 HTTPS／443，使用已有的公开地址校验、DNS 固定和逐跳重定向保护；不发送 OAuth Token、Cookie 或 Client Secret。目录响应最大 1 MiB，首页最大 512 KiB，图标最大 8 MiB；站点导入有总超时，图像最多 1600 万像素。远程图标不受整合包域名白名单影响，但沿用 Worker 下载代理配置。没有使用第三方 favicon 代理服务。

## 人工上传和裁剪

在“联盟管理 → 组织 → 编辑”中上传或更换头像，也可重新裁剪既有原图或移除图片。上传支持静态 PNG／JPEG／WebP，最大 8 MiB；三分网格、拖动、方向键、滑杆与重置沿用服务器箴言的交互，固定 1:1 选区，保存结果为 512×512。

具有本组织 `ORG_EDIT` 的网页管理会话或超管可以修改；仅能读取本组织的管理账号可以预览。普通成员、外组织管理员和 API Token 不能调用管理头像接口。上传解码和对象写入在数据库事务外执行，提交时重新校验会话、归属、归档和 `expectedRevision`，避免并发编辑覆盖。

人工上传、重新裁剪和移除都会将 `avatarMode` 设为 `MANUAL`，自动同步不会覆盖。移除后也不会在下一分钟重新装回网站头像。当前界面没有“恢复自动头像”按钮；再次修改可继续人工上传。新组织先保存资料，再进入编辑上传头像。

原图、成品和元数据使用独立不可变目录 `organization-avatars/{organizationId}/{uuid}/`。旧版本与竞争失败产生的未引用对象暂不自动回收，沿用服务器箴言现有边界；不影响客户端 CAS、发布和签名。

## 超管 Settings 同步板块

“Union 组织目录同步”只对超管显示，接口也逐请求检查超管 Cookie。面板每 10 秒读取状态，显示上次尝试、最近成功同步、下次计划、上游版本、收到／已同步记录数、本次新建数、网站／人工头像数及等待／失败数。

状态为等待首次同步、正在同步、已同步、部分同步、失败或过期。超过 3 分钟没有成功同步为过期；最近请求失败显示失败，同时保留上次成功时间。头像失败单独统计，不伪装成整个 API 不可用。“立即同步”只提前 Worker 到期时间，不在网页请求里执行抓取；Worker 未运行时不会虚报已同步。
