# 界面语言与黑白主题

登录页右上方和管理界面顶部提供语言／主题按钮，所有账号均可使用，不需要 MUA 超管权限。支持简体中文（`zh-CN`）和英文（`en-US`）；默认简体中文、白色主题。主题按钮在白色／黑色之间切换，不强制跟随操作系统。

语言 Cookie `mua-locale` 保存一年（Path=/、SameSite=Lax，HTTPS 时 Secure），服务器在登录／后台认证通过之后读取并传给客户端 Context，保留原登录重定向状态。localStorage 同名键用于同源标签页同步。主题由已有 next-themes 保存至 localStorage `mua-theme`，通过 `html.dark` 驱动完整 CSS 变量。首屏脚本在绘制前恢复已保存主题与 `html.lang`，避免先显示错误主题；状态来自枚举白名单，不将 Cookie 内容直接插入脚本。

切换立即更新组件文案，保留正在填写的表单与既有 `/admin` 路由。业务名称、组织别名、用户填写的简介／Markdown、服务器地址、版本号、文件名及接口权限标识不翻译或改写。词典和模板仅用于界面文案、已知校验／探测提示；无法识别的底层诊断保留原信息，避免隐藏错误。

界面使用 next-intl，采用稳定语义键和中英文独立词典：

界面文案采用简洁、自然的表达：标题说明内容，按钮说明操作，提示先写发生了什么，再写用户可以做什么。中英文按各自习惯表达，英文使用句式大小写。面向用户的说明使用“后台处理”“文件检查”“安装包”等常用词；必要的格式名称、版本、权限标识和技术接口文档仍保持准确。控制台为管理首页的统一名称，签名页不显示开发环境提示。目录同步页将头像和简介归入“网站基础信息”，最近一次同步的结果显示在“同步日志”中。

- `src/lib/locales/zh-CN.json`：手动修改中文文案。
- `src/lib/locales/en-US.json`：手动修改英文文案。

两个文件的键结构相同，按 `auth`、`navigation`、`clients`、`organizationAccess`、`api` 等命名空间组织。修改时只改右侧文案，保留左侧键名和占位符。例如修改 `auth.login.skinSite`，即可调整“使用皮肤站登录”按钮，不需要修改组件，也不影响英文。旧版以中文句子为键的词典已经移除。

```json
{
  "auth": {
    "login": {
      "skinSite": "使用皮肤站登录"
    }
  }
}
```

新增文案时，在两个词典中添加同一语义键；文案调整不重命名键。组件可使用标准 `useTranslations("auth.login")` / `t("skinSite")`，现有界面通过 `useI18n().t("auth.login.skinSite")` 共享语言切换状态，底层同样使用 next-intl。共享表单和表格允许传入语义键或已经翻译的标签，业务选项仍需 `translate: false`。`src/i18n/request.ts` 提供基于现有 Cookie 的服务端配置；`PreferenceProvider` 显式传入 locale、messages、上海时区，使 SSR 与首次客户端渲染保持一致。路由继续使用 `/login`、`/admin` 等现有地址。

占位符使用 ICU 语法，如 `validation.maxCharacters` 中的 `{max}`，调用 `t("validation.maxCharacters", { max: 255 })`。两种语言应保留相同变量名；不要翻译变量名。字面量花括号按 ICU 规则写作 `'{}'`，单引号写作 `''`，富文本标签须遵循 next-intl 的 rich text 规则。API 文档中的字面量也由词典统一维护，修改后运行 `npm run openapi:generate` 更新生成文档。

API 错误统一返回英文 `error`、稳定的 `code` 和 `params`，不根据 Cookie 切换响应语言。前端保存错误码与参数，再通过中英文词典的 `diagnostics` 命名空间格式化，因此切换语言也能更新已经显示的错误。后端在产生诊断的位置直接指定语义码；不存在按中文或英文消息原文匹配的兼容层。

`src/lib/diagnostics.ts` 定义结构化诊断 `{ code, message, params }`。Worker 的警告、失败原因和进度，以及服务器探测提示，在 API 中使用该结构，`message` 为英文。诊断序列化后存入现有文本字段，读取时恢复结构；没有增加业务表。未携带结构的旧诊断不按原文恢复，返回通用诊断不可用提示。第三方未知请求错误保留英文诊断，无法凭文本猜测翻译键。组织名称、简介、审核说明、文件路径等业务内容保持原样。

网页请求失败由 `RequestError` 保留完整诊断，前端通过 `formatMessage(t, value)` 渲染；动态表单校验使用相同消息结构。手动修改系统提示仍只需编辑 `zh-CN.json`／`en-US.json` 的对应值，无需维护额外的原句映射文件。OpenAPI 5.0.0 记录新的错误和诊断结构，格式协议与发布签名没有改变。

`npm run test:admin-ui` 检查两份词典的键、ICU 语法和变量一致性，并验证中文文案可以独立修改、业务内容保持原样。`src/i18n/types.d.ts` 为标准 next-intl hooks 提供键名／语言的类型检查。未来新增语言还需扩展 locale、语言按钮及完整词典。

黑色主题覆盖页面、侧栏、弹窗、卡片、表格、输入框和 Toast；探测灯保留原颜色。服务器箴言图片继续按既有要求向白色淡出，空图文字在白色图片区域保持可读，不改变图片对象或签名。

验证包括词典插值完整性、中／英文登录／Settings／表格、业务内容保留、探测提示／日期、既有 RBAC 和发布格式回归，以及实际带 Cookie 的中英文页面和未登录重定向。生产构建检查 Cache Components 的请求边界。浏览器自动化桥不可用时，需明确区分这些检查与实际鼠标／截图验收。
