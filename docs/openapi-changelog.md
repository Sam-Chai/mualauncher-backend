# OpenAPI 兼容性记录

## 5.2.0 依赖升级兼容 · 2026-10-25

Zod 4 和新版生成器替换原依赖，修复注册时的扩展加载顺序及 RegExp 标志序列化问题；更新源码摘要和中英文产物。仅生成结构去除了重复的 anyOf null 分支，兼容性工具按等价语义归一化完全相同的 anyOf 分支；oneOf 及真实字段／nullable／认证／权限变化仍受检查。保留 5.2.0 和所有历史基线，完整 93／公开 11，无新增迁移或业务字段。现有共享配额不变，见 [整改与验收](dependency-security.md)。

## 5.2.0 · 2026-10-25 运行方式设置与执行实例

新增超管 Cookie 专用 `GET/PATCH /api/admin/execution-settings` 与 `GET /api/admin/execution-instances`，完整 93／公开 11。PATCH 必须包含 mode 和 revision；同源、实际会话、超管与新鲜 Worker 能力共同校验。只新增操作，不更改已有 HTTP 响应或 Launcher 协议；5.1.0 基线继续保留。

默认 DOCKER_GVISOR，不可用时禁用选择并继续等待，不自动降级。显式 BARE 由统一协议在宿主 Java 21+ 执行，只保证 JVM 堆、时间／日志及产物校验，不能提供容器权限和资源隔离。运行中任务绑定原模式；历史签名不改写。新增迁移 `202610250001_execution_management`，34 张业务表 FORCE RLS；执行实例由 Worker 写入，仅超管浏览器可读。

## 5.1.0 · 2026-10-23 敏感文件与账号凭据撤销

新增 `POST /api/auth/revoke-credentials`（本人浏览器，包含 PLAYER）及 `POST /api/admin/accounts/{accountId}/revoke-credentials`（超管浏览器），严格空 JSON、同源校验，返回受影响会话、API Token 和启动器授权数量。完整 90／公开 11；相对 5.0.0 无既有操作删除或请求响应结构变化，新增 5.1.0 基线并保留旧基线。

改密、重置密码、停用及超管标志变化会撤销全部 API Token 和 Launcher 授权；重新启用不恢复。新导入在下载及 CAS 前过滤敏感文件，旧草稿含敏感路径阻止新发布；不改写历史签名。见 [边界与契约](credential-revocation-and-pack-privacy.md)。

## 5.0.0 安全约束补充 · 2026-10-23

密码登录改为客户端及客户端与用户名组合配额，不再使用匿名请求可以耗尽的全站登录尝试预算；未配置可信地址头时设置非认证的 mua_login_client 限流 Cookie。API 文档修正已有 Session Cookie 为实现中的 SameSite=Lax，并描述错误凭据响应也可能设置限流 Cookie。上传 PUT URL 绑定保存记录计算出的精确 Content-Length（包括末片），拒绝大小不符或缺少长度的请求。现有 Blob／Buffer 客户端无须更改。

这是既有参数约束落实及说明校正，无操作、JSON 字段、权限、有效期或签名产物协议变更；OpenAPI 保持 5.0.0、完整 88／公开 11，保留现有基线。Next.js 与 eslint-config-next 同步升级到 16.4.1；Forge 执行隔离和敏感文件过滤留待下一轮。

## 5.0.0 · 2026-10-22 英文 API 诊断与前端翻译

开发期统一错误响应为 `{ error, code, params }`：error 始终为英文，code 为稳定语义标识，params 为插值参数。Worker 的失败原因、警告、进度以及探测提示改为 `{ code, message, params }`，message 为英文。前端只按 code 查询中英文词典，不再匹配旧中文消息。此为错误／诊断契约的主动调整；新增 public/admin-5.0.0 基线，接口数量仍为完整 88、公开 11。muapack 文件格式、内容身份、签名、RBAC 和授权范围保持不变。迁移 `202610220004_english_diagnostic_default` 仅将 PackageBuild 的兜底进度默认值改为英文。

同日组织简介增量：目录通过各站 `/api/yggdrasil` 的 `meta.serverName` 自动填充组织简介。既有组织 PATCH 在真实修改／清空简介后永久保留人工内容，省略或原样保存不停止同步；字段、路径、权限及操作数不变，仅补充行为说明。见 [目录同步](union-directory-sync.md)。

新增 providers、yggdrasil/start、yggdrasil/exchange 及超管 launcher-providers GET/PUT，完整 88 操作。公开子集扩至 11 操作，包含启动器必需认证及成员自查，管理 Cookie 与 mul_/mua_ 权限仍隔离。新接口严格 JSON、一次性请求、固定来源在线验证，按 CODE:UID 识别账号，签发不超过 15 分钟的只读 Token。开发期主动调整公开范围，无兼容旁路；新增 public/admin-4.0.0 基线并保留旧记录。见 [实施说明](launcher-game-token-exchange.md)。

## 3.2.0 · 2026-10-21 PLAYER 与 Union 登录身份

组织成员角色增加 `PLAYER`（玩家），没有管理权限；组织成员 PUT 的空角色输入归一化为 PLAYER，单服授权不接受 PLAYER 或 ORG_ADMIN。账号响应和管理状态 actor 新增可选 `unionSubject`，在成员列表、账号目录和添加成员搜索中展示完整 Union 身份，不伪造本地 username；账号搜索同时支持完整 sub。

对比 3.1.0，变化涉及 GET 管理状态、GET 账号搜索、PUT 组织成员和 PUT 单服授权四个操作，无操作增删，公开 Launcher 契约不变。新角色是请求／响应枚举扩展；单服授权枚举移除原先实现已拒绝的 ORG_ADMIN 并排除 PLAYER，属文档校正。用户已授权开发期直接调整，审核后保存 public-3.2.0／admin-3.2.0 新基线并保留 3.1.0；完整规范仍为 83 操作。

## 3.1.0 · 2026-10-21 组织皮肤站地址

`GET /api/admin/state` 的组织响应新增可选 `skinSites: [{ code, url }]`，从已启用的 Union 来源映射投影，供组织资料、列表及“前往皮肤站”使用。没有已启用映射时省略该字段。普通管理会话只可读取所属组织的地址；全局映射管理及写权限仍限超管。

这是响应字段的增量扩展。对比 3.0.0，只有此操作的响应模式变化，没有移除或新增操作，公开 Launcher 契约无变化。审核后新增 public-3.1.0／admin-3.1.0 基线，保留 3.0.0；完整规范仍为 83 操作。

同日 YITUEM 合并补充：`skinSites` 可包含同一 CODE 的两个不同 URL，前端以 CODE＋URL 区分条目并分别提供按钮。既有数组模式无需变化，版本与基线保持 3.1.0；数据库仍仅有一个 YITUEM 身份映射，额外域名通过受限别名字段保存。

## 3.0.0 · 2026-10-21 Union 目录与组织头像

新增超管目录同步状态／立即同步和组织头像读取／上传／移除共 5 个操作，完整规范 83 操作；公开仍四个需要登录的 Launcher GET。组织创建／编辑 JSON 删除 `avatarObjectKey` 输入，头像必须经过限制图片类型、512×512 裁剪、组织权限和修订校验的独立 multipart 接口。这是用户授权的开发期请求契约调整，不保留裸对象键写入；保留旧基线，审查后新增 public-3.0.0／admin-3.0.0 基线。CODE 校验按实际上游名单支持数字，例如 TEST2；不会合并不同完整 sub。

每分钟同步由受限 Worker 租约执行，超管网页只读取持久状态或提前安排任务；普通成员、非超管管理员、Launcher 和管理 ApiToken 无权读取该状态。现有资源授权、下载、包格式、签名和发布保持。见 [目录同步与头像](union-directory-sync.md)。

## 2.0.0 · 2026-10-21 Union 登录与成员访问

这是用户明确接受的开发期破坏性认证变化，不保留匿名兼容分支；包格式、签名、已发布数据和固定版本刷新完整性校验不变。保留 1.0.0 基线，新增 public-2.0.0／admin-2.0.0 基线并继续检查。实现与未验证边界见 [Union 成员访问](union-oauth-member-access.md)。
